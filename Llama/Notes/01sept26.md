# wake2vec devlog 2026-09-01

> *P3 launch*

## Llama 3.1-8B P3 LAUNCH 

P2 is complete and written up: cut at 1300, best val 5.1486, 0.181 beneath the 3B's capacity wall with its entire overfit region below that wall, and a generation battery that closed the code-register leak and came back ~70% verified Wake-lexicon 
retrieval. P3 starts from `step_0900`.

### launch config

| | value |
|---|---|
| Adapter source | `wake2vec_llama8b_p2_lora/full_checkpoints/step_0900` |
| Embedding source | `embeddings_frozen.pt` (split source: P2 saved embeddings once) |
| Morph loss | **cosine**, the quantity the analysis reports |
| λ_morph / λ_device | **1.0** / 2.0 |
| Filters | strip groups excluded, **movable pairs only** |
| Optimizer | **Adafactor** (see below) |
| LR / steps | 2e-5 / 1000, patience 3, eval and save every 100 |
| Batch / SEQ_LEN | 1 x 16 / **512**, matching P1 and P2 so val stays comparable to 5.1486 |
| Embeddings | Wake rows unfrozen, base rows gradient-masked |

Adafactor is forced. the 8B's embedding matrix is 172,451 x 4096, so 706M parameters, and the gradient mask zeroes gradients after they are materialised, so the optimizer carries state for the whole matrix. under AdamW that is ~5.65GB of fp32 moments 
on top of a 4-bit body (~3.5GB), the bf16 embedding (~1.41GB), its gradient (~1.41GB) and activations: it does not fit a T4. Adafactor stores no momentum, and it is the project's own precedent for this exact problem (Qwen P1). the cost is that the 
optimizer is no longer held constant against the earlier P3 runs.

the P2 battery came back at roughly 70% verified Wake-lexicon retrieval, 42 confirmed tokens against 16 inventions, nearly all of the confirmed ones occurring only once or twice in the entire corpus (`cettehis`, `sengentide`, `athemisthued`, 
`rooksacht`, `eddaying`), placed in grammatical position, and stable across independent samples.
